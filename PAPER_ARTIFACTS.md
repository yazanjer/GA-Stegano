# Paper artifacts in this repository

Every number in the manuscript *Adaptive Multi-Directional Traversal Path Optimization for
Image Steganography Using Genetic Algorithms with Enhanced Message Decomposition Strategy* is
generated by this pipeline. The two run directories the paper cites are committed here, so the
figures and tables can be re-derived from a fresh clone without re-running the experiments.

| Run | Directory | What it produced |
|---|---|---|
| A | `outputs/amdt_rebuttal/2026-08-10_16-54-07/` | Imperceptibility, ablation, payload statistics, runtime, significance. 29 covers x 5 seeds (0-4). |
| B | `outputs/amdt_rebuttal/2026-08-11_02-08-16/` | Steganalysis on 1,000 BOSSBase 1.01 covers, single root seed. |

## What is and is not committed

For each of those two runs the repository carries `results/`, `tables/`, `figures/`,
`index.json`, `provenance.json`, `dataset_pin.json` and `resolved_config.yaml` -- about 19 MB.

Deliberately excluded: the 8.7 GB of stego images under `stego/`, the 5.3 GB
`cnn_payload.zip`, the `wandb/` directories, all other run directories, and the run logs
(which carry absolute machine paths). `.gitignore` records the exact rules.

## Path redaction

Absolute paths in the committed run metadata have been rewritten to relative ones --
`baseline_images/im1.jpg`, `data/BOSSbase_1.01/1.pgm` -- so the repository does not publish a
local home directory. **Only path strings were changed.** Every SHA-256, every metric and every
numeric field is byte-identical to what the pipeline emitted, so the manifests still pin the
corpora exactly.

## The embedding key is not a secret

`configs/main.yaml` sets

```yaml
secret_key_hex: "2a7f4c9e1b6d80f3a5c2e7091d4b8fa63e5c1908d7b2a4f60c3e819d5a7b2f4c"
```

This is a **fixed demonstration key, published on purpose.** Layers T3 and T4 are keyed, so
reproducing the payload-statistics results requires the same key the runs used; it appears in
both runs' `resolved_config.yaml` and `provenance.json` for that reason.

It is not a credential and it protects nothing here -- no stego images produced with it are
published. **Any real use of this scheme must supply its own key**, via
`stego.secret_key_hex=<hex>` on the command line or by editing the config. Do not reuse this
one.

Genuine credentials -- `kaggle.json`, `.env`, `*.pem`, `*.key`, W&B API keys -- are excluded by
`.gitignore` and none is present in this history.

## Reproducing the paper's numbers

```bash
pip install -r requirements-local.txt
pytest -q                      # 216 correctness tests
```

The manuscript's verification script re-derives 70 headline values straight from the CSVs in
the two run directories above. Point it at this clone and every check should pass.

## Known gaps in the recorded provenance

- Both manifests record `"Git commit": None`: the runs were made before this repository
  existed, so no commit hash could be captured. Re-running under version control will fill it.
- Run B's `seed_policy` string asserts that results are averaged over five root seeds, while
  the same object records `seeds: [0]`. The single-seed fact is the accurate one and is what
  the manuscript states; the policy string is a fixed default that is not run-specific.
